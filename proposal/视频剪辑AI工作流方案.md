# 视频剪辑 AI 工作流方案

> 面向：抖音 / 快手短视频剪辑师
>
> 目标：把"翻素材、听写、粗切、对字幕、找废片、卡节奏"这些机械劳动压到最低，把省下的时间留给你真正值钱的部分——判断和审美。
>
> 版本：v1.0（2026-10-17）｜配套调研见 `research/`，可行性验证见 `demo/` 与 `pipeline/`

---

## 0. 一页结论

**你的四个要求，技术上分别对应四件事，而且不需要"等一个全能 AI"，现在就能拼出来：**

| 你的要求 | 本方案的做法 | 成熟度 |
|---|---|---|
| ① 整理素材：提音频、出文本、理解内容、按逻辑切片 | 本地 ffmpeg 抽音轨 → 云端 ASR 出带时间戳文稿 → 视觉大模型出分镜描述 → 按"句群 + 镜头切点"切片 | 成熟，需一个 API Key |
| ② 去掉无意义分片 | 规则层（黑场/冻帧/静音/模糊/重复台词）+ 模型层（信息密度/情绪/NG）打分，**只标记不删除**，出复核表 | 成熟，规则层零成本 |
| ③ 按我的想法剪成粗剪，最好能用剪映编辑 | 你说一句话 → 结构化成剪辑脚本 → 生成 **剪映专业版工程文件**，打开就是多轨时间线 | **已在本机实测跑通**（见 §4） |
| ④ 抖音/快手流量建议 | 把平台机制翻译成 46 项可执行的剪辑参数；一稿出**抖音版/快手版**两套节奏 | 调研完成，见 §5 |

**三个关键判断，先说在前面：**

1. **不做"一键成片"，做"一键粗剪 + 可复核表格"。** 全自动成片在短视频这种强审美场景下必然平庸；但"把 4 小时压到 1 小时，且每一步你都能改"是可以做到的，而且这才是剪辑师愿意用的形态。
2. **中间产物必须是你能看懂、能改的文件**（表格 / JSON / 分镜表），不是黑盒。你改完一句"第 3 段换成 12 秒那个镜头"，重跑一步就出新版本。
3. **AI 的边界要划清楚**：它负责"找、切、排、对字幕、卡点"；你负责"选哪条、怎么讲、什么情绪"。方案里每个环节都标了"你要做的决定"。

## 1. 调研结论

### 1.1 把需求拆成可计算的 6 个环节

你口中的"整理素材"，其实混了六件不同的事，混在一起做才觉得难：

```
素材入库 → 转写理解 → 语义切片 → 废片判定 → 按意图编排 → 出工程/审片 → 平台适配
```

每一环的输入输出都是文件，可以单独重跑、单独检查。这是整个方案的地基。

### 1.2 工具盘点：手上已经有什么

| 能力 | 现成工具 | 状态 |
|---|---|---|
| 抽音轨 / 裁剪 / 拼接 / 混音 / 压制字幕 | `mediakit-cli`（本地 ffmpeg） | ✅ 本机可用 |
| 语音转字幕（带时间戳、说话人） | `mediakit-cli video asr-subtitles`（云端） | ⚠️ 需 `MEDIAKIT_API_KEY` |
| 智能语义切片（按停顿/镜头切、不切断句子） | `mediakit-cli video semantic-segment`（云端） | ⚠️ 需 Key |
| 视频理解 / 带时间戳分镜描述 | `mediakit-cli video video-understand-router --scene editing` | ⚠️ 需 Key |
| 画面文字 OCR / 高光拆条 / 场景切分 | `mediakit-cli video video-ocr / analyze-video-highlights / segment-scenes` | ⚠️ 需 Key |
| 剪映工程生成 | 本方案自研（`pipeline/to_jianying.py`） | ✅ **已实测** |
| 快速审片预览 | 本方案自研（`pipeline/render_preview.py`，ffmpeg） | ✅ 已实测 |
| 草稿静态校验（防"内容已损坏"） | `research/validate_draft.py` | ✅ 已实测（含负向对照） |

**唯一的硬门槛：一个火山引擎 / MediaKit 的 API Key（环境变量 `MEDIAKIT_API_KEY`）。** 没有它，云端 ASR 和视频理解跑不了，只能走本地 whisper（慢 5–10 倍、需要装模型、中文标点更差）。建议先开一个跑小样。

### 1.3 剪映工程这条路，到底通不通？

这是整个方案风险最高的一环，所以我在你机器上真跑了一遍（剪映专业版 11.0.0）：

**做到了什么：**
- 用程序生成了一份包含「2 段视频 + 2 条字幕」的时间线草稿 `ai-poc-02`，装进剪映草稿库；
- 剪映启动后，**"本地草稿"里正常显示**：封面正确、时长 00:06、体积 4.6M，无"内容已损坏"、无"媒体丢失"（截图见 `demo/剪映11-程序生成草稿-验证截图.png`）；
- 结构校验器 `validate_draft.py` 全绿：**OK=15 / WARN=0 / FAIL=0**，且"与剪映 11.0 自身 schema 相比无缺字段"；
- 反向对照也做了：故意注入 4 处错误（路径不存在、同轨重叠、悬空引用、时长不符）→ 4 条 FAIL、退出码 1，证明校验器不是"永远 PASS"。

**没做到什么（如实说）：**
- 没能在自动流程里双击打开它、看到时间线渲染——剪映弹了一个"版本更新"模态框，挡住了模拟点击。**这一步需要你手动双击确认一次（1 秒的事）**。
- 所以当前证据强度是：**"剪映接受并正确索引了这份草稿"**，加上**"结构与剪映自己写出的完全同构"**；"时间线渲染正常"仍是待你确认的最后一格。

**技术上踩到的三个真坑（都已解决，写进代码）：**
1. Mac 版剪映是 **App Sandbox**，只能读 `~/Movies` 和草稿目录里的 `Resources/`。素材放桌面、放 `/tmp`，打开就是"暂无访问权限"或静默丢素材 → 方案里默认把素材**打包进草稿的 Resources/**。
2. 现成库 pyJianYingDraft 生成的草稿**共用同一个 draft_id**，多份草稿会索引撞车 → 已改成每份重新生成。
3. 它引用的部分附属素材没写进 JSON（悬空引用）→ 已做清理，并把整体套进剪映 11.0 自己写的空草稿骨架，做到字段级同构。

**降级预案**（万一 11.0 某个小版本改了格式）：素材 + 分镜表 + 预览片三件套仍然可交付，你按分镜表在剪映里重组，只是回到手动拖时间线；或临时用剪映 5.9（Win）/ 5.5.0（Mac），旧格式完全明文，兼容性最稳。

### 1.4 平台机制：三个直接影响剪辑的事实

（完整调研见 `research/抖音快手流量调研.md`，46 项参数、红线清单、25 条带日期来源）

1. **抖音的权重从"看完"转向"存下 + 回访 + 关注"**。2025-04 开放日官方口径是"预测行为概率 × 行为价值权重"，完播率被多目标稀释，新增了收藏率、"收藏+复访""关注+追更""打开+搜索"、探索指标。→ 对剪辑的含义：**结尾要设计"值得存"的东西**（清单/方法/地址），而不是单纯求赞。
2. **快手先过"点开"这一关**。双列分发，封面和标题决定点击率；同时私域/关注页权重远高于抖音。→ 同一条素材，**快手版封面要更"人话"、时长可以多 20–30%、结尾要能导向直播**。
3. **"加字幕、改画幅、换背景"在平台眼里不算原创**。抖音 2026-03 短剧公告明确把"简单加工"列为治理对象；法院判例的尺子是"是否可替代原作"。→ 二创的护城河只能是**信息增量**（观点/资料/出镜），不是技术处理。

## 2. 方案总览

### 2.1 流水线

```
                      ┌─────────────────────────────────────────────┐
 原始素材（多条/长录像） │  0 素材入库    ffprobe 台账 + 抽帧联系表      │
                      └──────────────────┬──────────────────────────┘
                                         ↓
                      ┌─────────────────────────────────────────────┐
                      │  1 转写理解    音轨 → ASR 文稿 → 视觉分镜描述 │
                      └──────────────────┬──────────────────────────┘
                                         ↓
                      ┌─────────────────────────────────────────────┐
                      │  2 语义切片    句群 + 镜头切点 → segments    │
                      └──────────────────┬──────────────────────────┘
                                         ↓
                      ┌─────────────────────────────────────────────┐
                      │  3 废片判定    规则 + 模型打分 → 复核表      │
                      └──────────────────┬──────────────────────────┘
                                         ↓   ← 你在这里改：删哪条、留哪条
                      ┌─────────────────────────────────────────────┐
                      │  4 编排        brief → 剪辑脚本 edit_plan   │
                      └──────────────────┬──────────────────────────┘
                                         ↓   ← 你在这里改：结构、时长、钩子
                      ┌─────────────────────────────────────────────┐
                      │  5 出工程      timeline.json                │
                      └───────┬──────────────────────┬──────────────┘
                              ↓                      ↓
                     剪映草稿（可编辑）        preview.mp4（快速审片）
                              ↓
                     6 平台适配：抖音版 / 快手版、封面、标题、发布
```

### 2.2 中间产物（全部人可读）

| 文件 | 内容 | 你要不要看 |
|---|---|---|
| `materials.json` | 素材台账：路径/时长/分辨率/帧率/音轨/拍摄时间 | 扫一眼 |
| `transcript.json` | 逐句文稿 + 时间戳 + 说话人 + 画面描述 | 不用看 |
| `segments.json` | 切片：每段起止、文本、语义标签、价值分 | 抽查 |
| `junk_report.csv` | 废片清单：时间码、原因、置信度、建议 | **必看，5 分钟** |
| `edit_plan.json` | 剪辑脚本：结构槽位、选段、目标时长、节奏 | **必看，10 分钟** |
| `timeline.json` | 时间线：轨道、入出点、字幕、音频 | 一般不用 |
| 剪映草稿 | 打开即多轨时间线 | **在这里精修** |
| `preview.mp4` | 预览片（字幕已压） | 用来快速否掉方案 |

**设计原则：**
- **单一事实来源**：所有出口都从 `timeline.json` 生成，改一处，草稿和预览同时变。
- **默认不删素材**：废片只标记，你确认后才生成"剔除版"。误删一条好素材的代价，远大于多看 20 行表格。
- **幂等 + 可回退**：每次生成带版本号，不覆盖旧稿；素材用文件哈希做缓存，加一条素材只重算它。

## 3. 六个环节详设

### 3.1 素材入库（0 成本，秒级）

- 扫描目录 → ffprobe 读时长/分辨率/帧率/码率/音轨/旋转/拍摄时间；
- 抽 3 帧生成"联系表"（contact sheet），让你 10 秒扫完 50 条素材；
- 统一编号（`A001_20261017_1430.mp4`），后续表里都用这个号，不认原始文件名。

**你要做的决定**：有没有不需要进项目的素材（直接剔除）。

### 3.2 转写与理解（云端，1 小时素材约 2–4 分钟）

- 抽音轨：`ffmpeg -vn -ac 1 -ar 16000`（本地，免费）；
- ASR：带**词级/句级时间戳 + 说话人分离**。这是后面所有"按句子切"的基础；
- 视觉理解：`video-understand-router --scene editing`，输出"带精确时间戳的分镜描述"（景别、人物、动作、情绪、场景）；
- 可选 OCR：画面里有字幕/文字（屏幕录制、采访字幕条）时补一遍。

产物：每句话 = `{起, 止, 文本, 说话人, 置信度, 画面描述, 景别, 情绪}`。

> 成本控制：视频理解按抽帧计费，默认 **0.2–1 fps 粗扫**；只有进入粗剪的片段才做 1–2 fps 精读。1 小时素材的抽帧量差 5 倍，钱也差 5 倍。

### 3.3 语义切片（云端 + 本地双保险）

两种切法互补，取交集：

| 方法 | 做什么 | 优点 |
|---|---|---|
| 云端 `semantic-segment` | 按停顿、镜头切换、叙事边界切，保证不切半句 | 语义完整 |
| 本地句群算法 | 3–5 句一个意群；句间停顿 > 0.4s 处吸附 | 免费、可解释 |

关键细节：**切点吸附到"气口"**。硬切在句子中间，观众会觉得"卡了一下"；吸附到换气处，观感立刻顺。

产物：`segments.json`，每段带 `{id, 来源, 起, 止, 文本摘要, 语义类型(开场/观点/论证/例子/情绪/收尾), 时长}`。

### 3.4 废片判定（这是最省钱的一环）

**规则层（本地，免费，先跑）：**

| 信号 | 判定 | 阈值起点 |
|---|---|---|
| 黑场 / 纯色 | ffmpeg `blackdetect` | > 0.5s |
| 冻帧 / 静止 | `freezedetect` | > 2s 且无语音 |
| 静音 | `silencedetect` | > 3s 且画面无变化 |
| 模糊 / 失焦 | `blurdetect` | 模糊度 > 0.3 |
| 过曝 / 欠曝 | `signalstats` YAVG | < 16 或 > 235 |
| 无音轨 | ffprobe | — |

**模型层（便宜，判内容）：**

| 类型 | 判定方式 | 处理 |
|---|---|---|
| 填充词过多 | "嗯/啊/那个/就是/然后"占比 > 15% | 建议剪掉填充段（不是整段删） |
| 重复 NG | 近 60s 内文本相似度 > 0.85 | **保留最好一遍**（音量/语速/停顿综合评分） |
| 场记/指令 | 出现"卡/再来一遍/三二一/走" | 建议删 |
| 无信息 | 无语音 + 画面无变化 + > 3s | 建议删 |
| 价值低 | 模型按"信息增量/情绪强度/可复用性"打 1–5 分 | 低分进待定区 |

产物：`junk_report.csv`

```
编号   来源        起-止          时长   原因              置信度  建议
S012   A003        00:12:31-00:12:38  7.0s   重复台词(NG)      0.92   删（保留 S009）
S015   A003        00:14:02-00:14:09  7.0s   填充词密度 23%    0.81   剪内部停顿
S021   A005        00:03:11-00:03:19  8.0s   无语音+静止       0.97   删
S033   A005        00:21:40-00:21:52  12.0s  信息密度低        0.55   待定（你自己看）
```

**你要做的决定**：5 分钟过一遍，把"待定"里你觉得能用的标 `keep`。这一张表通常能砍掉 30–50% 的无效素材。

### 3.5 按你的想法编排（核心）

**输入**：一句话 + 可选参数

```yaml
想法: 把这次探店剪成 45 秒，前 3 秒放最炸的出品镜头，中间讲三个卖点，结尾引导到店
平台: 抖音
时长: 45s
风格: 快节奏、信息密度高
必须出现: "招牌牛肉面"、"凌晨四点熬汤"
不要出现: 老板的正脸（他没同意出镜）
```

**处理**：把你的想法解析成**结构槽位**，再从 `segments.json` 里检索填充。

| 槽位 | 时长 | 需求 | 选段逻辑 |
|---|---|---|---|
| hook 钩子 | 0–3s | 结果前置 / 反常识 / 冲突 | 视觉冲击力最高 + 无需上下文 |
| setup 铺垫 | 3–10s | 交代人物/场景 | 含主体、画面稳定 |
| proof 论证 | 10–30s | 信息点 ×3 | 信息密度高、每 5–8s 换镜 |
| turn 反转 | 30–38s | 情绪/认知转折 | 情绪分最高 |
| cta 收尾 | 38–45s | 到店/关注/收藏 | 口播清晰、有具体动作 |

**校验器**（生成后自动跑，不过就重排）：
- 总时长 ±10%
- 相邻镜头不同源（避免跳切违和）
- 单镜头时长在平台区间内（口播 3–5s / 剧情 1.5–3s）
- 字幕每行 ≤ 14 字、单屏停留 ≥ 1.2s
- 口播字数 ≈ 语速 × 时长（5 字/秒）
- BGM 时长 ≥ 成片时长

产物：`edit_plan.json` + 一张**人话版分镜表**（Markdown/Excel），你直接在上面改"第 3 段换成第 7 条素材的后半段"。

### 3.6 出工程 + 审片（两种出口，一份数据）

```
timeline.json ──┬──→ to_jianying.py  ──→ 剪映草稿（V1 视频 / A1 原声 / A2 BGM / T1 字幕）
                └──→ render_preview.py ──→ preview.mp4（9:16、字幕已压、可直发审片）
```

- **剪映草稿**：素材已打包进工程 `Resources/`，打开即用，不报"媒体丢失"；字幕是**独立文本轨**（不是烧死的），你可以在剪映里改样式、改错别字。
- **预览片**：不用等剪映导出，30 秒出一版 6s/45s 的预览，用来快速否掉"结构不对"的方案。
- **两条出口同源**，不会出现"预览和工程不一样"。

**你要做的决定**：在剪映里做审美层的精修——调色、音效、转场手感、字幕样式。这部分 AI 不该碰。

## 4. 剪映工程落地（技术细则）

### 4.1 已验证的生成路径

```
素材 + timeline.json
   → pyJianYingDraft 生成 5.9 格式时间线
   → 清理悬空引用、重写 draft_id
   → 媒体打包进 Resources/，path 改写为安装后绝对路径
   → 套用剪映 11.0 自己的空草稿骨架（字段级同构）
   → 写 draft_info.json（Mac 入口）+ draft_meta_info.json
   → 注册进 root_meta_info.json（先备份，失败回滚）
   → validate_draft.py 门禁
```

### 4.2 必须遵守的格式规则（踩过的坑）

| 规则 | 说明 |
|---|---|
| 时间单位 | **微秒**（1s = 1_000_000），不是秒、不是帧 |
| id | 素材/片段/轨道用 32 位小写 hex；草稿 id 用大写 UUID，且 content / meta / 索引三处一致 |
| 素材路径 | 裸绝对路径，不要 `file://`、不要 URL 编码 |
| Mac 沙盒 | 媒体必须在 `~/Movies` 或草稿 `Resources/` 内，否则"暂无访问权限" |
| 轨道下标 | `render_index` 必须等于轨道在数组里的下标 |
| 附属素材 | 每个视频片段必须有一条 `speed` 素材，否则行为异常 |
| 入口文件 | Mac 版读 `draft_info.json`；同内容另存 `draft_content.json` 兼容 Windows 工具 |

### 4.3 交付形态（按你的风险偏好选）

| 形态 | 内容 | 适用 |
|---|---|---|
| A. 草稿直装 | 剪映草稿 + 分镜表 + 预览 | 默认，最省事 |
| B. 素材包 + 分镜表 | 切好的片段 + 表格 + 预览，你在剪映里重组 | 剪映升级导致格式不认时的兜底 |
| C. 纯分镜表 | 只有表 + 时间码 | 你想完全手动 |

## 5. 流量：把平台机制翻译成剪辑参数

> 完整 46 项参数与来源见 `research/抖音快手流量调研.md`。这里只放最影响剪辑决策的部分。
> **所有数值都是起点，不是真理**：一次只改一个变量，3 条一组，看 24 小时 + 7 天两组数据。

### 5.1 抖音 vs 快手：同一条素材，两套剪法

| 维度 | 抖音版 | 快手版 |
|---|---|---|
| 前 3 秒 | 直接上冲突/反常识，不留呼吸 | 先交代人物场景，3–5 秒再抛冲突 |
| 时长 | 30–60s 主力 | 60–120s 可接受（多 20–30%） |
| 字幕 | 更快更碎，关键词高亮 | 整句、字号略大（中老年用户多） |
| 封面 | 强冲突大字 | 人物 + 场景 + 一句人话（双列要可读） |
| 结尾 | 关注 + 追更 / 搜索词 | **直播预告** + 关注 |
| 分发逻辑 | 单列，拼 5 秒留存 | 双列，拼封面点击率 |

**这就是"一稿两版"的价值**：同一批素材，参数换一套，多拿一个平台的量。

### 5.2 剪辑决策清单（精选 18 条）

| # | 参数 | 起点值 | 依据 |
|---|---|---|---|
| 1 | 首帧 0s | 必须有信息事件（人脸/动作/冲突/大字），禁止黑场、LOGO、BGM 淡入 | 经验 + 单列机制 |
| 2 | 钩子句 | 前 3 秒台词 ≤ 15 字 | 经验 |
| 3 | 第一个信息点 | ≤ 5 秒必须兑现，不能只挖坑 | 经验 |
| 4 | 口播单镜 | 3–5 秒必须变化（跳剪/推拉/B-roll/花字） | 经验 |
| 5 | 剧情单镜 | 1.5–3 秒；冲突段 0.8–1.5 秒 | 经验 |
| 6 | 信息点间隔 | 每 5–8 秒一个；每分钟 8–12 个 | 经验 |
| 7 | 小高潮 | 每 10–15 秒一次 | 经验 |
| 8 | 语速 | 4.5–5.5 字/秒（270–330 字/分） | 经验 |
| 9 | 口播字数 | 15s≈75 字 / 30s≈150 字 / 60s≈300 字 | 与语速自洽 |
| 10 | 字幕每行 | 12–14 字，最多 2 行，单屏 ≤ 28 字 | 可读性 |
| 11 | 字幕字号 | 字高 90–110px（≈屏高 4.5–6%） | 可读性 |
| 12 | 字幕位置 | 距底 15–20%，避开评论/购物车 UI | 产品 UI |
| 13 | 字幕停留 | 每屏 ≥ 1.2 秒 | 阅读速度 |
| 14 | BGM 音量 | 比人声低 12–18dB | 音频工程 |
| 15 | 前奏 | 0–0.5 秒内必须有声音事件，不要 BGM 淡入 | 5 秒止损 |
| 16 | 主 CTA | 30s 片在第 22–27 秒；60s 片在第 48–55 秒 | 经验 |
| 17 | 追更 CTA | 结尾 2–3 秒，≤12 字，必须带**下条具体内容** | 官方"关注+追更" |
| 18 | 封面 | 3:4（1080×1440），文字 6–10 字，人脸 ≥1/3 | 行业通用 |

### 5.3 红线（会直接毁号，比优化重要）

| 行为 | 判定 |
|---|---|
| 完整搬运、掐头去尾、替换文案伪装原创 | 明确违规 |
| 加字幕/改画幅/换背景/加一句话解说 | **平台认定为"简单加工"，不算原创** |
| 用马赛克遮挡他人水印 | 明确违规 |
| 影视二创"看完短视频就不用看原片" | 法院判例认定"可替代原作"，不构成合理使用 |
| AI 生成画面/配音未标注 | 违反《AI 生成合成内容标识办法》（2025-09-01 施行） |

**一句话**：二创的护城河是"提供了多少原作没有的东西"（观点、资料、出镜、对比），不是"改了多少刀"。

## 6. 日常怎么用

### 6.1 你的操作（最小路径）

```
你：把素材丢进一个文件夹，说一句「剪成 45 秒探店，前 3 秒放最炸的，结尾引导到店，发抖音」
 ↓
AI：入库 → 转写 → 切片 → 废片表 → 分镜表 → 剪映草稿 + preview.mp4
 ↓
你：5 分钟过废片表（标 keep/drop）→ 10 分钟过剪辑脚本（改结构）
 ↓
AI：重跑 → 出新版本草稿
 ↓
你：剪映里精修 20–30 分钟 → 导出 → 发布
```

### 6.2 时间账（估算，1 小时素材出 60 秒成片）

| 环节 | 现在 | 方案后 |
|---|---|---|
| 听素材、记时间码 | 60–90 min | 0（文稿代替） |
| 粗剪搭结构 | 60–90 min | 10 min（改脚本） |
| 对字幕 | 30 min | 5 min（改错别字） |
| 找废片/重复条 | 20–30 min | 5 min（看表） |
| 选 BGM / 卡点 | 20–30 min | 10 min |
| 导出审片 | 15 min | 0（预览片即时看） |
| **合计** | **约 3.5–4.5 小时** | **约 50–60 分钟** |

> 这是估算，取决于素材规整度和你对 AI 选段的接受度。第一次会慢一些（要调参数），跑顺之后边际成本很低。

### 6.3 角色分工

| AI 做 | 你做 |
|---|---|
| 听写、打时间码、找重复 | 判断哪条"有感觉" |
| 按句子/镜头切 | 决定叙事顺序和取舍 |
| 出结构初稿 | 改节奏、加情绪 |
| 对字幕时间轴 | 改文案、调样式 |
| 卡点、配音量 | 调色、音效、转场手感 |
| 出双平台参数版 | 决定发哪个、什么时候发 |

## 7. 成本、风险与边界

### 7.1 成本构成

| 项 | 说明 |
|---|---|
| 本地处理（抽音轨/切片/预览/废片规则） | 0 元，只吃 CPU |
| 云端 ASR | 按音频时长计费；1 小时素材约 2–4 分钟（经验值，以实测为准） |
| 云端视频理解 | 按抽帧量计费，**这是大头**；用"粗扫 + 命中精读"两级策略可降 3–5 倍 |
| 运行环境 | 需 `ffmpeg` + Python 3.10+ + `pip install pyJianYingDraft` |
| 剪映 | 免费版足够；导出 4K/去水印等增值项另算 |

**建议**：先拿 3 条真实素材跑通，量一下单条成本，再决定抽帧档位。

### 7.2 风险清单

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| 剪映升级改草稿格式 | 中 | 高 | 锁版本；`validate_draft.py` 门禁；B 形态兜底 |
| 云端 API 权限/额度 | 中 | 中 | 先用小样；本地 whisper 备选 |
| 素材隐私 | 低 | 高 | 只上传音频和抽帧；敏感素材走本地模式 |
| AI 选段不合口味 | 高 | 低 | 表格可改，改完重跑 |
| 版权/二创判定 | 中 | 高 | 红线清单；只做有信息增量的二创 |
| 老板/客户改需求 | 高 | 低 | 改 `edit_plan` 重跑，不动素材 |

### 7.3 明确不做什么

- **不做全自动成片**：审美层不碰，避免"一眼 AI"。
- **不自动删除素材**：只标记，删除权在你。
- **不做去水印/擦字幕洗稿**：既违规也没用（平台不认）。
- **不替代剪映**：输出的是"可编辑的粗剪"，精修仍在剪映。

## 8. 实施路线

| 阶段 | 内容 | 产出 | 验收标准 |
|---|---|---|---|
| **P0（1–2 天）** | 打通单条素材：入库 → 转写 → 切片 → 废片表 → 剪映草稿 | 一条 60s 粗剪 + 一张废片表 | 你在剪映里能打开、能改、能导出 |
| **P1（1 周）** | 编排层：brief → edit_plan → 校验器；预览片 | 一句话出一个粗剪版本 | 改一句想法，10 分钟内出新版 |
| **P2（2 周）** | 双平台参数、封面选帧、标题/话题建议、批量处理 | 一稿两版 + 发布包 | 抖音版/快手版同时产出 |
| **P3（按需）** | 数据回流：发布后数据 → 反推剪辑参数 | 你自己的基线表 | 每周自动生成"哪种钩子留存高" |

## 9. 需要你确认的 6 件事

1. **素材类型**：口播 / 剧情 / 探店 / 影视解说 / 直播切片？不同类型，切片策略差很多。
2. **单条素材典型时长**：10 分钟？1 小时？3 小时？决定要不要分批处理。
3. **愿不愿意用云端 API**：愿不愿意开一个 `MEDIAKIT_API_KEY`（决定能不能自动转写和理解）。
4. **剪映版本**：确认就是 11.0.0，且能接受"草稿由程序生成"这种方式。
5. **要不要我先做 P0**：你给 1–2 条真实素材，我直接出一版粗剪 + 废片表，你验一下手感。
6. **发布节奏**：一周几条？有没有固定人设/栏目？决定要不要做批量模板。
