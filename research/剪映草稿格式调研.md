# 剪映（JianyingPro / CapCut 国内版）草稿工程程序生成调研

> 目标：程序生成剪映草稿，剪辑师打开就能继续编辑。
> 调研对象：本机 **剪映专业版 11.0.0**（`/Applications/VideoFusion-macOS.app`，bundle id `com.lemon.lvpro`，`CFBundleShortVersionString = 11.0.0`，已签名 `Developer ID Application: Shenzhen Lianmeng Technology Co.Ltd.`，**启用 App Sandbox**）。
> 草稿根目录：`/Users/developer/Movies/JianyingPro/User Data/Projects/com.lveditor.draft/`
> 环境：macOS（arm64）、`/opt/homebrew/bin/{python3,node,ffmpeg}`、Python 3.13.12（venv）用于 pyJianYingDraft。

## 0. 结论摘要（TL;DR）

| 问题 | 结论 | 置信度 |
|---|---|---|
| 能不能程序生成可编辑草稿？ | **能**。旧格式 `draft_content.json` 体系（明文 JSON）在 11.0.0 上可用；本机已实测"能被剪映列出、时长/封面正确" | 高（列表级已验证，时间线渲染未验证） |
| 单位 | **微秒**（1 s = 1 000 000）。整份文件没有秒字段 | 高（实测） |
| id 关联 | 素材/片段/轨道用 **32 位小写 hex**；草稿 id 用**大写带连字符 UUID**。`segment.material_id` → `materials.xxx[].id`；`segment.extra_material_refs[]` → `speeds/transitions/material_animations` 等 | 高（实测） |
| path 格式 | **绝对 POSIX 路径，裸路径**。不要 `file://`，不要 URL 编码，不要反斜杠 | 高（实测字段 + 剪映自己写出的值） |
| 11.0 认不认旧格式 | **认**。二进制里保留 `draft_content.json` 读取/迁移路径；本机 11.0 生成的空草稿里 `template.tmp` 就是旧格式的全量 JSON；并行轨道实测 11.0.0 列表已显示程序生成的草稿 | 高 |
| 11.0 的 `draft_info.json` 加密影响吗 | **不阻塞**。11.0 自己写出来的 `draft_info.json` 是 `jianying_draft_encrypt_v2`（AES+RSA 信封）密文，但**明文 JSON 放进 `draft_info.json` 也被读取**（实测：并行轨道把 `draft_content.json` 原样复制成 `draft_info.json`，剪映正常列出） | 高（读侧）；写侧伪造密文不可行 |
| pyJianYingDraft 能用吗 | **能，但只到 10.8 语义**。0.3.1 官方表格标"新版剪映 10.8 ✅"，未声明 11.0；实测其产物缺 11.0 的 9 个 `materials` 分类与 7 个顶层字段（属"多余可缺省"方向），11.0 仍能列出 | 中高 |
| 最稳交付路线 | **① 明文 `draft_content.json`（+ `draft_info.json` 复制一份）+ 注册 `root_meta_info.json` + 素材 bundle 进草稿目录**；不碰加密、不碰新格式。若目标机器是 Windows 新版且只认密文，再降级/换路线 | — |

**一句话**：剪映 11.0 仍然把"明文旧格式"当合法输入（并在保存时自己迁移/加密），所以"程序生成明文旧格式草稿"是当前性价比最高、风险最低的路线；真正脆弱的不是格式，而是 **素材路径（sandbox）、draft_id 冲突、`render_index` 层级、以及资源 id（转场/字体/特效）**。

## 1. 本机取证事实

### 1.1 草稿目录现状

`com.lveditor.draft/` 下 13 个目录（12 个用户草稿 + 并行轨道新建的 `ai-poc-01`）+ `root_meta_info.json`。

三种格式状态并存：

| 目录 | `draft_content.json` | `draft_info.json` | `template.tmp` | `Timelines/project.json` |
|---|---|---|---|---|
| `4月19日` | 无 | **密文**（base64，6340 B） | **明文**（3892 B） | 有（431 B 明文） |
| 其余 11 个 | 无 | **密文** | 无 | 有（431~461 B 明文） |
| `ai-poc-01`（程序生成） | **明文** | **明文**（与前者字节相同） | 无 | 无 |

> `draft_meta_info.json` 在这 12 个老草稿里**也是密文**（base64）。`draft.extra` 是二进制（非 JSON）。

### 1.2 决定性取证：`template.tmp` 是旧格式全量明文

`4月19日/template.tmp`（3892 B）是**明文 JSON**，键集合与旧版 `draft_content.json` 完全一致（`materials` / `tracks` / `canvas_config` / `config` / `duration` / `fps` / `version` / `keyframes` / `platform` …），并且：

```json
{
  "version": 360000,
  "new_version": "75.0.0",          // 11.0.0 自己写出的"协议号"
  "draft_type": "video",
  "duration": 0, "fps": 30.0,
  "canvas_config": {"background": null, "height": 0, "ratio": "original", "width": 0},
  "platform": {"app_id": 0, "app_source": "", "app_version": "", "device_id": "",
               "hard_disk_id": "", "mac_address": "", "os": "", "os_version": ""},
  "last_modified_platform": { …同上，全空… },
  "tracks": [],
  "materials": { /* 54 个分类，全部为空数组 */ }
}
```

**两个重要结论**：

1. 11.0 的**内部时间线模型仍然是旧格式 schema**，只是外面套了 `Timelines/<uuid>/` 与加密壳；"新版"不是新 schema，而是新**容器**。
2. 11.0 自己生成的草稿 **`platform` / `last_modified_platform` 全为空字符串**——即 11.0 **不校验机器指纹**。那些 `device_id` / `hard_disk_id` 只在真正保存过内容的草稿里才被填。→ 手写草稿不必伪造指纹。

（`7月20日`、`6月24日` 的 `Timelines/<uuid>/template.tmp` 同样 `version=360000`、`new_version=75.0.0`、platform 全空、`canvas 0x0`、`duration 0`。）

### 1.3 加密机制取证（为什么不要试图伪造密文）

对 `libvideoeditor.dylib`（169 MB）做字符串取证（`strings -a`，587 096 条）：

| 证据 | 位置（行号） | 含义 |
|---|---|---|
| `jianying_draft_encrypt_v2` | 363633 / 538018 | 加密方案代号 |
| `N12_GLOBAL__N_123EncryptStringKeyIVMuxerE` | 363640 | "key + IV" 打包器 → 对称加密（有 IV） |
| `lvve::EncryptUtilsImpl::encryptAES / decryptAES` | 363646-363649 | 明确的 AES 加解密入口 |
| `CryptoPP::GCM_Final<CryptoPP::Rijndael…>`、`CBC_Encryption/Decryption` | 367385-367483 | 用 Crypto++，AES-GCM / CBC 都在 |
| `CryptoPP::PK_Encryptor / PK_Decryptor`、`AgMBAAE=`（DER 里 `02 03 01 00 01` = RSA e=65537） | 367290-367303 / 403788-403796 | **RSA 公钥**：信封加密，AES 密钥被 RSA 包裹 |
| `crypto_key_store.cpp`、`CryptoKeyStore`、`kGlobal/kCurrent/kTemporary`、`key_store do_uncompress error` | 403780-403900 / 363660 | 密钥存本地 key store（压缩存储） |
| `draft_cover.jpg / draft_meta_info.json / template.tmp / draft.json / draft_info.json / draft_content.json / draft_cloud_material.json / template-2.tmp` | 363376-363383 | **读取器认识的全部草稿文件名**（`draft_content.json` 与 `template.tmp` 并列在册） |

密文实测（`4月19日/draft_info.json`）：

```
base64 长度 6340 → 解码 4753 B；4753 % 16 == 1；前 16 B = dc2f0526a69e1e0e…
不同字节值 256 个（全熵）→ 1 字节头 + 4752 B（= 16 × 297）密文体
```

→ **1 字节版本头 + 16 字节对齐的 AES 密文**。没有 RSA 私钥/本地 key store 就无法产出合法密文，所以**不要走"自己写密文"这条路**；要么写明文（剪映读），要么调用剪映自己的原生库（见 §7.4）。

## 2. 旧格式 `draft_content.json` 完整字段说明

### 2.0 文件清单与最小必需集

| 文件 | 必需 | 内容 | 备注 |
|---|---|---|---|
| `draft_content.json` | **是** | 时间线主体（本文件 §2 全部内容） | 顶层无 `timelines`，直接就是一条时间线 |
| `draft_meta_info.json` | **是** | 草稿名、`draft_id`、封面路径、`tm_duration`、素材池 | 剪映列表卡片的直接来源 |
| `draft_info.json` | 建议 | 11.0 的"活动时间线"。**可以就是 `draft_content.json` 的明文副本** | 索引 `draft_json_file` 指向它 |
| `draft_settings` | 否 | INI 文本：`[General]` + `draft_create_time` / `draft_last_edit_time` / `real_edit_keys` / `real_edit_seconds` / `cloud_last_modify_platform=mac` | 缺了也能开 |
| `draft_cover.jpg` | 否 | 列表缩略图 | 剪映会自己重生 |
| `draft.extra` | 否 | 二进制 | 不要手写 |
| `draft_virtual_store.json`、`attachment_*.json`、`key_value.json`、`timeline_layout.json` | 否 | 各种附件 | 程序生成可全部省略 |
| `Timelines/`、`template.tmp` | 否 | 新格式容器 | 走旧格式路线时**不要创建** |

最小可打开集合 = `draft_content.json` + `draft_meta_info.json`（+ 媒体文件可访问）。

**video**（`materials.videos[i]`）

| `crop_ratio` | `"free"` / `"preset"` | |
| `crop_scale` | `1.0` | |
| `audio_fade` | `null` | |

`crop` 的 8 个键是**四角归一化坐标**（不是 left/top/right/bottom）：
`{upper_left_x, upper_left_y, upper_right_x, upper_right_y, lower_left_x, lower_left_y, lower_right_x, lower_right_y}`，全画面 = `(0,0)(1,0)(0,1)(1,1)`。

**audio**（`materials.audios[i]`）：`id` / `local_material_id` / `music_id`（三处同值）、`name`、`path`、`duration`（微秒）、`type:"extract_music"`、`category_name:"local"`、`check_flag:3`、`app_id:0`、`source_platform:0`、`copyright_limit_type:"none"`、`effect_id:""`、`formula_id:""`、`wave_points:[]`。

**text**（`materials.texts[i]`）——注意**正文在 `content` 这个"JSON 字符串"里**：

```jsonc
{
  "id": "e1b2…f90",
  "type": "text",
  "content": "{\"text\":\"这是字幕\",\"styles\":[{\"fill\":{\"alpha\":1.0,\"content\":{\"render_type\":\"solid\",\"solid\":{\"alpha\":1.0,\"color\":[1.0,1.0,0.0]}}},\"range\":[0,5],\"size\":12.0,\"bold\":false,\"italic\":false,\"underline\":false,\"strokes\":[{\"content\":{\"solid\":{\"alpha\":1.0,\"color\":[0,0,0]}},\"width\":0.08}]}]}",
  "alignment": 1,            // 0 左 / 1 中 / 2 右
  "typesetting": 0,
  "letter_spacing": 0.0,
  "line_spacing": 0.02,
  "line_feed": 1,
  "line_max_width": 0.82,
  "force_apply_line_max_width": false,
  "check_flag": 15,          // 位标志：有描边=+8 等，按需叠加
  "global_alpha": 1.0
}
```

`content.styles[].range` 是**字符区间**（`[start, end]`，`end` = 文本长度），按 UTF-16 计；样式按区间分段，逐字不同色就是多个 style。

**speed**：`{id, type:"speed", mode:0, speed:1.0, curve_speed:null}`

**transition**：`{id, type:"transition", name:"叠化", effect_id:"322577", resource_id:"6724845717472416269", duration:500000, is_overlap:true, platform:"all", category_id:"", category_name:""}` —— **`effect_id`/`resource_id` 必须是剪映资源库里的真实值**，否则打开后显示"转场加载失败"。`TransitionType` 枚举里有 453 个可用值。

### 2.4 `tracks` 与 `segments`

**track**

```jsonc
{
  "id": "aa00…01",          // 32 hex
  "type": "video",           // video / audio / text / effect / filter / sticker（导入时还有 adjust）
  "name": "主视频",
  "is_default_name": false,
  "flag": 0,                 // 0 普通；主轨也常是 0
  "attribute": 0,
  "segments": [ … ]
}
```

**segment**（视频/音频/文本通用）

| 字段 | 说明 |
|---|---|
| `id` | 32 hex，全局唯一 |
| `material_id` | → `materials.<cat>[].id` |
| `target_timerange` | `{start, duration}` 微秒，**时间线上的位置** |
| `source_timerange` | `{start, duration}` 微秒，**素材内的入出点**；文本片段为 `null` |
| `speed` | float，与 `materials.speeds` 中那条的 `speed` 一致 |
| `volume` | 0~1（音频/视频都支持） |
| `extra_material_refs` | 数组，指向 speeds / transitions / material_animations / canvases / sound_channel_mappings / audio_fades / 蒙版 等 |
| `clip` | 画面变换：`{alpha, flip:{horizontal,vertical}, rotation, scale:{x,y}, transform:{x,y}}`；音频片段为 `null` |
| `render_index` | **= 所属轨道在 `tracks` 数组中的下标**，决定叠放层级（越大越上） |
| `track_render_index` | 一般 `0` |
| `visible` / `reverse` / `is_tone_modify` / `last_nonzero_volume` / `track_attribute` | 照抄（`true/false/false/1.0/0`） |
| `enable_adjust`, `enable_color_*`, `enable_lut`, `enable_smart_color_adjust` | 7 个 `enable_*` 布尔，照抄 |
| `uniform_scale` / `hdr_settings` | 视频有；音频可省 |
| `common_keyframes` | 关键帧数组，无则 `[]` |
| `keyframe_refs` | `[]` |

**关键帧**（`segment.common_keyframes[i]`）：`{id, keyframe_list:[{time_offset, values:[…], curve_type:"Line"}], material_id, property_type:"KFTypePositionX" …}`；`time_offset` 是**相对片段起点的微秒**。`property_type` 取值是 `KFType*` 字符串，dylib 里能搜到 **231 个**不同的 `KFType*`。已逐个核对存在的高频项：`KFTypePositionX`、`KFTypePositionY`、`KFTypeScaleX`、`KFTypeScaleY`、`KFTypeRotation`、`KFTypeAlpha`、`KFTypeVolume`、`KFTypeSaturation`、`KFTypeContrast`、`KFTypeBrightness`、`KFTypeZoom`、`KFTypeLUT`。
> ⚠️ 不存在 `KFTypeMask`（实测 `grep -c` 为 0），蒙版打关键帧用的是 `KFTypeAdjustColorMask*` 一族（`…MaskPostionX`（原文拼写就是 Postion）、`…MaskSizeWidth`、`…MaskFeather`、`…MaskRotation` 等）。

### 2.5 单位与取值域

| 量 | 单位 / 范围 |
|---|---|
| 所有时间 | **微秒**（int）。`1s = 1_000_000` |
| `volume` | 0 ~ 1（超过 1 是增益，剪映面板上限 2 左右） |
| `speed` | 0.1 ~ 100（面板）；文件里是 float |
| `clip.transform.x/y` | **-1 ~ 1**，0 = 画面中心；y 正方向**向上** |
| `clip.scale.x/y` | 1.0 = 原始大小；0.35 = 35% |
| `clip.rotation` | **度**（不是弧度） |
| `crop.*`、`line_max_width`、`letter_spacing` | 归一化 0~1（字号 `size` 是"磅"，面板值 1~30 左右） |
| `draft.duration` | 微秒，= max(target.start + target.duration) |

### 2.6 id 关联规则

```
draft_content.id  ──(=)──  draft_meta_info.draft_id  ──(=)──  root_meta_info.all_draft_store[].draft_id
        │                                                     uppercase UUID with dashes
        ├── tracks[].id            32 hex
        ├── tracks[].segments[].id 32 hex
        ├── materials.*[].id       32 hex  ←──── segment.material_id
        └── materials.{speeds,transitions,…}[].id  ←──── segment.extra_material_refs[]
```

三条硬规则：

1. **每段必带 1 条 speed 素材**（即使 1.0×）。缺了剪映会用默认值，但第三方工具（pyJianYingDraft 重写、jianying-tool 编辑）会认为缺件。
2. **转场挂在前一段的 `extra_material_refs`**，`duration` 是"重叠时长"（叠化 500000 = 0.5 s），不是转场素材长度。
3. **`render_index` 必须等于轨道下标**。实测 pyJianYingDraft 就是这么写的（`segment_json["render_index"] = export_index`）；写错会导致字幕被视频盖住这种"看起来像 bug"的问题。

### 2.7 path 规则（Mac 尤其重要）

| 规则 | 说明 |
|---|---|
| 绝对 POSIX 路径 | `/Users/xxx/Movies/…/clip.mp4` |
| **不要 `file://`** | 剪映自己写的是裸路径 |
| **不要 URL 编码** | 含空格/中文都直接写原字符（JSON 里 UTF-8） |
| 不要相对路径 | 剪映不做 cwd 解析 |
| **必须落在沙盒可读范围** | 见 §6：11.0 是 **App Sandbox** 应用，只带 `assets.movies.read-write` 等 entitlement |

## 6. Mac 版特殊要求

### 6.1 入口文件名：`draft_info.json` 是"活动时间线"

- 索引里的 `draft_json_file` 指向 `draft_info.json`；11.0 自己的草稿**只有** `draft_info.json`（密文）+ `Timelines/`。
- 但读取器文件名单里 `draft_content.json` 与 `template.tmp` 都在（§1.4），且 `readDraftJsonSync` 有"空则读 `template.tmp`"的回退。
- **最稳做法：把同一份明文 JSON 同时写进 `draft_content.json` 和 `draft_info.json`**（并行轨道实测就是这样，剪映认），这样无论它走哪条分支都能读到。

### 6.2 platform 指纹：11.0 不校验

- 11.0 自己生成的 `template.tmp`：`platform` / `last_modified_platform` **9 个字段全为空串**。
- pyJianYingDraft 模板：`{app_id:3704, app_source:"lv", app_version:"5.9.0", os:"windows"}`。
- 并行轨道 `macify` 改成：`{app_id:3704, app_source:"lv", app_version:"5.4.0", os:"mac"}` → 也能被列出。
- **结论**：指纹不是门槛；填"看起来合理的 mac 指纹"即可，别留 Windows 指纹（低风险但没必要）。
- 顺带一个好用的信号：`new_version` 是"协议号"（11.0=`75.0.0`，5.9/6.x=`110.0.0`，mac 5.5.0 的 `draft_info.json`=`103.0.0`）。

### 6.3 sandbox：**这是 Mac 上最容易翻车的地方**

`codesign -d --entitlements` 实测：

```
com.apple.security.app-sandbox                       = true
com.apple.security.assets.movies.read-write          = true
com.apple.security.files.user-selected.read-write    = true
com.apple.security.files.bookmarks.app-scope         = true
com.apple.security.files.bookmarks.document-scope    = true
com.apple.security.network.client/server             = true
com.apple.security.device.audio-input / camera       = true
com.apple.security.cs.allow-jit / allow-dyld-environment-variables = true
```

含义与对策：

1. **剪映是沙盒应用**，原生能自由读写的位置主要是 `~/Movies`（`assets.movies.read-write`）与用户"选择过"的文件（bookmark）。
   → 这解释了为什么草稿根目录在 `~/Movies/JianyingPro/…`。
2. **素材放在 `~/Movies` 之外（例如 `/tmp`、`~/Desktop`、外接盘未授权）时，很可能读不到**，表现为"媒体丢失/黑屏"，而不是报错。**高置信推断**（基于 entitlement，未做 A/B 实测）。
   → **对策：素材必须落在 `~/Movies` 下，或者直接 bundle 进草稿目录**（草稿目录本身在 `~/Movies` 里，天然可读）。
3. bundle 的做法（并行轨道的 `bundle_media=True`、`jianying-tool bundle` 同理）：把媒体复制进 `<草稿>/Resources/`（或 `<草稿>/media/`），**再把 `materials.*[].path` 改写成新绝对路径**。实测 `ai-poc-01/Resources/clipA.mp4` 这条路走通了。
4. 不同机器草稿根目录不同 → **生成器不要把根路径写死**，用参数/环境变量（`JIANYING_DRAFT_ROOT`）。

### 6.4 `root_meta_info.json` 注册

- 结构：`{"all_draft_store":[…], "draft_ids": <int，历史遗留，别当数组用>, "root_path": "…/com.lveditor.draft"}`。
- 每个条目的关键字段：

```jsonc
{
  "draft_id": "BC69C7CD-…",                     // = draft_meta_info.draft_id
  "draft_name": "ai-poc-01",
  "draft_fold_path": "…/com.lveditor.draft/ai-poc-01",
  "draft_root_path": "…/com.lveditor.draft",
  "draft_json_file": "…/com.lveditor.draft/ai-poc-01/draft_info.json",   // ← 指向活动时间线
  "draft_cover": "…/ai-poc-01/draft_cover.jpg",
  "draft_timeline_materials_size": 4849915,      // 素材总字节
  "tm_duration": 6000000,                        // 微秒
  "tm_draft_create": 1792243577743818,
  "tm_draft_modified": 1792243577743818,
  "tm_draft_removed": 0,
  "streaming_edit_draft_ready": true,
  "draft_new_version": "",
  "draft_is_invisible": false,
  "cloud_draft_cover": false, "cloud_draft_sync": false, …
}
```

- 剪映启动时会 `Find {} drafts in {}` 再 `Merge {} drafts to root_meta_info.json` ——**会扫描目录并回写索引**，所以"目录在、索引没登记"多数情况下也能被发现（第三方 `jianying-tool` 把 `unregistered` 归为 **warning** 而非 error）。
- 但**必须避免索引脏数据**：索引里有、目录已删（`dangling`）是 **error**，且用这个名字再建草稿会被剪映判为「草稿内容已损坏」（`jianying-tool` 文档明确警告）。删草稿要连索引一起删。
- **剪映运行时改索引无效**：索引由剪映按内存清单回写（`jianying-tool` 文档："索引由剪映按内存里的清单写回，开着的时候去改不生效"）。→ **程序写草稿要在剪映退出时做**。
- 本次并行轨道 install 时保留了 `root_meta_info.json.20261017-212617.bak`，这是好习惯，建议固化。

## 7. 路线对比与建议

### 7.1 四条路线

| 路线 | 兼容性 | 工作量 | 可维护性 | 主要风险 |
|---|---|---|---|---|
| **A. 明文旧格式 `draft_content.json`（+ `draft_info.json` 副本）** | 本机 11.0.0 列表已验证；5.9~10.8 广泛验证；Windows 新版待验 | **低**（一个 JSON 生成器 + 元信息 + 注册） | 高（schema 稳定 3 年未变） | 沙盒路径、draft_id 冲突、资源 id |
| **B. `template.tmp` 注入（新格式容器）** | 需要构造 `Timelines/project.json` + `template.tmp` + 合法密文 `draft_info.json`，**最后一环做不出来** | 高 | 低（每版可能变） | 密文写不了 → 只能依赖"明文回退"分支，等于绕回 A |
| **C. 调剪映原生库编解码**（`libvideoeditor.dylib` 的 `EncryptUtils::encryptAES/decryptAES`） | 理论上 100%（就是剪映自己） | **很高**（C++ ABI、沙盒子进程、版本脆弱） | 低 | 私有 API 无保证；杀毒/公证/版本升级即碎 |
| **D. 换交换格式（FCPXML / EDL / 达芬奇工程）** | 剪映**不支持**导入 FCPXML/EDL（无此入口）；达芬奇/Pr 支持 | 中 | 高 | 需要剪辑师换软件，或"剪映只做最后包装" |

> B 路线实测死结：`draft_info.json` 是 AES+信封加密（§1.3），**没有密钥无法生成合法密文**；而 `template.tmp` 虽是明文，但它只是"单条时间线主体"，外层 `project.json` 指向的 `draft_info.json` 仍会被优先读取。除非剪映走"读空→回退 `template.tmp`"分支，否则注入不生效。
> D 路线补充：`jianying-tool` 这类工具也是走 A/C 混合（能读明文就读明文，读不了才起原生库子进程），没有绕开格式本身。

### 7.2 推荐落地路线（分三步，风险递增）

**第 1 步（现在就能交付）：A 路线 + 打包**

1. 以 `base_template_11.0.json`（本机 11.0 自己写出的空草稿）为基底，注入 `materials` + `tracks`（用 `research/build_old_format_draft.py`）。
2. 素材 **bundle 进 `<草稿>/Resources/`**，`path` 写成绝对新路径（避免沙盒/换机）。
3. 写 `draft_content.json` + **同内容 `draft_info.json`** + `draft_meta_info.json`（**改掉 `draft_id`/`draft_name`/`draft_fold_path`/`tm_duration`**）+ `draft_settings` + `draft_cover.jpg`。
4. 在剪映**退出**状态下注册 `root_meta_info.json`（先备份）。
5. 用 `research/validate_draft.py` 做交付前自检（0 FAIL 才发）。

**第 2 步：灰度验证**
让剪辑师先打开、只做"看一眼 + 拖一下片段 + 保存"的冒烟测试；**保存后剪映会迁移成密文新格式**，此后该草稿只能由剪映维护（程序不要再改它，或改前先复制一份明文备份）。

**第 3 步（若 11.x 后续版本不认明文）**
优先**降级剪映**（见 7.3），而不是去啃原生库。

### 7.3 如果 11.0 不认，降级到哪一版最稳

| 目标 | 版本 | 理由 |
|---|---|---|
| **首选** | **剪映 5.9（Windows）** | pyJianYingDraft 官方"全绿"基线；`new_version=110.0.0`；社区案例最多 |
| 次选 | 剪映 6.x（Windows） | 自动导出仍可用（≤6.8）；格式与 5.9 一致 |
| 可用 | 剪映 10.8 | 官方"新版剪映 10.8"列全绿（除自动导出） |
| mac 备选 | 剪映 **5.5.0**（macOS） | 第三方 `jianying-tool` 的 macOS 基线；此版 `draft_info.json` 是**明文**（协议号 103.0.0），不需要处理加密 |
| 避免 | 11.x（Windows/macOS 新版） | 写密文、容器化，程序侧只能"喂明文赌它读" |

> 注意：降级要**同时**降 `new_version`（11.0 写 `75.0.0`；5.9/6.x 写 `110.0.0`），否则老版本可能把草稿判为"来自更新版本"而拒绝。本脚本 `--flavor legacy` 就是干这个的。

### 7.4 关于"原生库路线"（备选，不推荐先做）

本机二进制已确认能力齐备：`lvve::EncryptUtilsImpl::{encrypt,encryptAES,decrypt,decryptAES}`、`EncryptStringKeyIVMuxer`、`CryptoKeyStore`（`kGlobal/kCurrent/kTemporary`）、`ResourceEncryptFunc/DecryptFunc`。第三方 `jianying-tool` 已经走通："遇到封装格式时会发现 Windows 的 `videoeditor.dll` 或 macOS 应用包内的 `Contents/Frameworks/libvideoeditor.dylib`，通过隔离子进程解码、修改并重新封装"。

代价：C++ 符号/ABI 绑定、必须在隔离子进程里跑（避免 DYLD 污染主进程）、沙盒与公证问题、剪映每次升级都可能变。**只有在"必须产出密文草稿"时才值得做。**

## 8. 风险清单（按严重度）

| 级别 | 风险 | 触发条件 | 缓解 |
|---|---|---|---|
| 🔴 高 | **素材被沙盒挡住**：`/tmp`、`~/Desktop`、外接盘路径读不到 → 黑屏/媒体丢失 | 素材不在 `~/Movies` 且未授权 | 素材落 `~/Movies`；或 bundle 进 `<草稿>/Resources/` 并改写 path |
| 🔴 高 | **`draft_id` 撞车**：pyJianYingDraft 默认全用同一个 id | 批量生成多个草稿 | 每个草稿重新生成 `draft_id`，并同步 meta/索引 |
| 🔴 高 | **索引脏数据 → 「草稿内容已损坏」** | 删了目录没删 `root_meta_info.json` 条目；或同名重建 | 增删草稿时同步维护索引；先备份 `.bak` |
| 🟠 中 | 剪映保存后**把草稿迁移成密文新格式**，程序再改旧文件无效 | 剪辑师打开并保存过一次 | 交付前保留明文母版；后续改动走"复制母版→再生成" |
| 🟠 中 | **转场/特效/字体资源 id 不存在或未缓存** → "xx 加载失败" | 用了冷门 `effect_id`/`resource_id` | 只用验证过的（如 `叠化 322577 / 6724845717472416269`）；或交付时不加转场 |
| 🟠 中 | `render_index` 写错 → 字幕被画面盖住 | 多轨时手工编号 | `render_index = tracks 数组下标`（脚本已自动规范化） |
| 🟠 中 | 悬浮 `extra_material_refs` | 手工抄 id 抄漏 | `validate_draft.py` 会 WARN；交付前清零 |
| 🟡 低 | `ms` 写法报错 / 时间单位混淆 | 用库的字符串 API | 统一微秒整数，或只用 `s` |
| 🟡 低 | `canvas_config 0×0` 导致画布"原始尺寸" | 忘了设 width/height | 显式写 1920×1080 |
| 🟡 低 | 字体未缓存 → 首次打开回落默认字体 | 用了第三方字体 | 用系统字体（如 `PingFang SC`）或接受一次回落 |
| 🟡 低 | 剪映运行时写索引会被覆盖 | 剪映开着时程序改 `root_meta_info.json` | 只在剪映退出时写 |
| ⚪ 信息 | 密文 `draft_info.json` 无法伪造 | 想走 B 路线 | 走 A 路线；或调原生库 |
