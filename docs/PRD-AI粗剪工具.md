## 1. 背景与问题

### 1.1 现状

一名剪辑师处理一条 60 分钟的现场素材、产出 3 分钟成片，现状耗时约 **4 小时**：
听素材 60–90 分钟、粗剪 60–90 分钟、对字幕 30 分钟、找废片 20–30 分钟、选 BGM/卡点 20–30 分钟。

### 1.2 上一版为什么失败

我们用一套自动流程做出了 2 分 56 秒的《九月一号》，剪辑师反馈：**"把一些重要的对话删掉了。"**

复盘数据：

| 指标 | 数值 |
|---|---|
| 有对话时长 | 47.7 分钟 |
| 进片对话 | 3.4 分钟（7%） |
| 被丢弃段落 | 130 / 140 |
| 被丢弃且含钱/合同/退费/就业/年龄信息的段落 | 24 段 |
| 「就业承诺」话题覆盖率 | 3.6% |
| 「其他学员故事」（非必留）覆盖率 | 9.7% |

**根因三条：**

1. **只用了文字一路信息。** 声音（强调、抢话、笑声）和画面（合同、印章、转账）没有进入决策。
2. **选段按"戏剧性"排序取前 N。** 没有信息保底，没有话题覆盖约束 → 金句挤掉条款。
3. **没有确认闸门。** 剪辑师第一次看到取舍，就是成片。

### 1.3 本产品的机会

不是"更聪明的自动剪辑"，而是**把 AI 的判断过程变成可检查、可修改、可反驳的东西**。
AI 负责"看懂素材、提出方案"，人负责"确认与裁决"，系统负责"按确认的结果施工"。

## 2. 产品定位

### 2.1 一句话

**把"看素材、听写、粗切、对字幕"从 4 小时压到 20 分钟人工介入，产出一个能在剪映里直接精剪的工程。**

### 2.2 做什么

| 做 | 说明 |
|---|---|
| 素材理解 | 声音 + 文字 + 画面三路分析，输出内容摘要与片段级判断 |
| 片段浏览 | 按时间 / 按分类两种视图，逐段试听、标记 |
| 人机确认 | 分析确认 + 3–5 个决策问题，答案直接驱动选段 |
| 覆盖式选段 | 先保话题，再挑句子，输出分镜表 |
| 预览与导出 | 预览片（无 BGM）+ 剪映工程 |

### 2.3 明确不做

- 不做全自动成片（审美、调色、音效、转场精修仍由人完成）
- 不做去水印、擦字幕、洗稿式"去重"
- 不做发布、投放、数据分析
- 不接管剪映：导出工程即止

## 3. 用户与场景

### 3.1 用户

| 项 | 描述 |
|---|---|
| 角色 | 剪辑师（非技术背景，会用剪映，不懂命令行） |
| 规模 | 1–2 人，个人/小工作室 |
| 设备 | Apple Silicon Mac；Windows 10/11 |
| 网络 | 可联网（允许音轨上传做转写、转写文本上传做理解，见 §7 隐私） |

### 3.2 典型场景

| 场景 | 素材 | 交付 |
|---|---|---|
| 活动纪实 | 40–60 分钟手持一镜到底 | 3 分钟纪录片 |
| 访谈/口播 | 20–60 分钟 | 60–90 秒 |
| 探店/产品 | 10–30 分钟多机位 | 45 秒 |
| 长素材切片 | 任意长 | 30 秒 × 3–5 条 |

### 3.3 使用约束（设计红线）

- 全流程人工操作时间 **≤ 20 分钟**，按下表分配（PLAN 验收、产品设计均以此表为准）：

| 环节 | 闸门 | 预算 |
|---|---|---|
| S2 浏览素材与片段 | — | 5 分钟 |
| S3 确认分析 + 裁决待定 | 闸门 A | 3 分钟（其中裁决待定 ≤ 2 分钟，见 FR-5） |
| S3 回答决策问题 | 闸门 A | 3 分钟（FR-6） |
| S4 看预览 + 核对未采用清单 | 闸门 B | 6 分钟 |
| 余量 | — | 3 分钟 |

- **素材原片不出本机**；只允许上传抽出的 16k 音轨（转写）和转写文本（LLM 理解），画面帧不上云
- 剪映工程必须能被剪辑师直接打开并继续编辑

## 4. 核心流程

```
S0 导入素材
S1 abc 分析（声音 / 文字 / 画面）          后台执行，可离开
S2 内容摘要 + 片段浏览器                    ★ 人在这里看素材
S3 确认分析 + 回答 3–5 个问题               ★ 人在这里定标准
S4 选段 → 预览片（无 BGM）                  ★ 人在这里看结果
S5 导出剪映工程 → 精剪
```

两道闸门：

- **闸门 A（S3 结束时）**：人确认分析结论、裁决"待定"片段、回答决策问题。
- **闸门 B（S4 结束时）**：人看过预览片、确认"未采用清单"无遗漏。

### 4.1 界面形态：六步项目向导（2026-10-20）

界面按上面的流程做成向导，一个项目一条步骤条：**① 新建 → ② 分析 → ③ 看素材 → ④ 定标准（闸门 A）→ ⑤ 看结果（闸门 B）→ ⑥ 导出**。详细规格见 [界面流程 v2](界面流程-v2.md)。

- 没走到的步骤不能点；走过的能回去改，改了之后下游标「需要更新」，不自动重跑
- 每个动作只有一个入口；后台任务一次一个，进行中其它启动类按钮置灰并说明原因
- 左侧项目列表保留，进入项目后自动收起成窄条，可固定展开
- 次要操作（项目设置、打开文件夹、清理缓存、API Key、诊断包、关于）收进「更多」菜单

## 5. 功能需求

优先级：P0 = MVP 必须；P1 = 首个可用版本；P2 = 后续。

### FR-1 项目与素材导入（P0）

- 新建项目：选择一条素材文件、填片名、选预设（纪实3min / 口播60s / 探店45s / 切片30s）、填剪辑偏好（FR-14，可跳过），然后「创建并开始分析」
- 成片目标时长由剪辑师定：新建时按「分 + 秒」填写，范围 10 秒–60 分钟，默认取预设时长、换预设不覆盖手填值（KI-92；CLI `aicut.py new … --target 秒`），之后可在 ⑤ 看结果随时改（CLI `aicut.py select … --target 秒`，只重跑选段，不转写、不调 LLM）
- 读取元信息：时长、分辨率、帧率、音轨、旋转
- 生成 540p 分析代理（用于浏览和定位，不用于成片）
- **验收**：导入 60 分钟、9GB 素材 ≤ 30 秒完成元信息读取；代理生成可后台进行

### FR-2 abc 三路分析（P0）

| 路 | 输入 | 输出 |
|---|---|---|
| a 声音 | 16k 单声道音轨 | 逐句能量、语速（字/秒）、停顿、抢话重叠 |
| b 文字 | 云端 ASR 结果 | 说话人、逐句文本、时间戳、置信度；话题分段；信息类型；实体 |
| c 画面 | 540p 代理片本地 1fps 抽帧（不上云） | 逐句画面质量：亮度、运动、清晰度 → 过暗 / 静止 / 抖动 / 虚焦标记；多镜头素材的镜头切点 |

- 景别、人脸数、OCR 文本、道具标签（合同/印章/手机）：**P2**。如做，须本地实现（§7：画面帧不出本机，不送云端视觉模型），一期不做
- 三路按时间对齐到同一个"内容单元"（一行 = 一句话）
- **验收**：60 分钟素材，端到端分析 ≤ 15 分钟；内容单元覆盖率 ≥ 95%

### FR-3 内容摘要（P0）

- 一段话说明"素材讲了什么"（≤ 80 字）
- 列出 3–6 个关键信息（带时间码）
- 列出主要说话人及各自时长
- **验收**：剪辑师确认摘要"基本正确"的比例 ≥ 90%（随机 10 条素材抽检）

### FR-4 片段浏览器（P0）

**两种视图**

| 视图 | 内容 |
|---|---|
| 按时间 | 逐段列出：时间码、分类、档位、摘要、时长、是否已用 |
| 按分类 | 按逻辑话题分组，每组头显示：可用/待定/废片数量、可用时长、建议时长 |

**必备元素**

- 每段可试听：从入点播到出点（播原素材，不生成切片），前后各留 0.3 秒
- 顶部分布条：全片时间轴，按档位上色，点击跳转
- 每段显示**档位依据**（人话，如"含关键信息：合同、退费、九千八"）
- 快速挑段：点击片段设为当前段，按 `S` 放入 / 移出「剪辑列表」（即必留段，与档位无关，见 §12），空格播放；右侧面板实时显示剪辑列表段数与合计时长 / 目标时长，超出时提示建议时长；可撤销
- 快捷键可自定义（「更多 → 快捷键」，本机全局生效，冲突时拒绝）；默认 空格 播放、↑↓ 换段、S 剪辑列表、A 可用、D 废片、X 不可用、Z 撤销
- 快捷筛选：全部 / 待定 / 可用 / 废片 / 剪辑列表 / 不可用 / 未用（界面在 ③ 看素材，KI-96）
- **验收**：140 段列表滚动流畅（≥50fps）；单段试听响应 ≤ 200ms

### FR-5 档位判定（P0）

| 档位 | 定义 | 处置 |
|---|---|---|
| **废片** | 无信息、重复、技术废（抖动/失焦/空镜/寒暄） | 不进候选 |
| **待定** | AI 拿不准（主体混杂、无关键词但篇幅长、低置信度） | 推入队列，人用 A/D 裁决 |
| **可用** | 有明确信息或画面价值 | 进入选段池 |

- 每段必须给出**理由**；无理由的判定视为不合格
- "待定"数量上限：总段数 × 28%（最少 10 段），约合 **≤ 40 段/60 分钟素材**，否则人会被淹没（代码 `pipeline/classify.py` 的 `MAX_PENDING_RATIO`）
- 超限时先把非保护段里信息最弱的降为废片；**必留话题段与 AI 标注失败段不自动降级**，超限只给警告、由人逐条裁决
- **验收**：PLAN §4 的 3 条验收素材上，每条待定 ≤ 上限；剪辑师裁决 40 段待定的耗时 ≤ 2 分钟（人工计时）

### FR-6 确认与提问（P0）

- 分析确认：摘要 + 三个证据入口（话题 / 关键信息 / 说话人），支持"分类改错"与"档位改错"
- 决策问题：3–5 个，由内容生成，每个都**绑定选段规则**
- 每个选项下方显示"选了会怎样"
- 问题示例：主角是谁 / 必须记住哪些信息 / 结尾落在哪个动作 / 能接受多长空白 / 哪些不能出现
- 确认页「保存并确认」后自动按答案重新选段（另一任务在跑时，答案照存并提示没能开始重选）
- 决策问题可重新生成；重新生成失败时原问题与答案保持不变，兜底模板生成的问题在页面上标明
- **验收**：答完 5 题 ≤ 3 分钟；每题都能在分镜表里追溯生效

### FR-7 选段与分镜表（P0）

**选段逻辑（覆盖优先，不是排序取前 N）**

1. 对话切分为 8–20 个话题（单个话题 ≤12 句；超长话题按时长切分并标注"1/4"）
2. 必留段（§12）整段先进片；必留话题与决策问题里勾选的「必须记住的信息」话题先占位
3. 每个必覆盖话题内选 1–3 句（信息分优先）
4. 剩余时长用"可用"段填充，保证 8–12 秒换镜
5. 硬约束：总时长 ±10%（目标时长由剪辑师定，见 FR-1）、说话人平衡、不重复、字幕每行 ≤14 字

**必留段超过目标时长**：必留段全部保留、不截断，选段结果给出建议时长；剪辑台自动弹窗请剪辑师重设目标（CLI 提示 `aicut.py select <项目> --target <秒>`）。出片前再核对一次分镜表是否覆盖每个必留段，缺了就停下并列出原话（GL-25）。

**产出**

- `分镜表`（人可读）：镜头号 / 时间码 / 台词 / 为什么选它 / 被删的替代句
- `timeline.json`（机器可读）

**手动修改与重新选段**：剪辑师手动改过分镜表（含字幕、顺序、入出点、加回）后，凡会触发重新选段的操作（改目标时长、重新确认答案、改必留 / 档位 / 不可用标记），先询问：「覆盖，用新的 AI 选段」/「保留我的修改」（只更新未采用清单和建议）/「取消」。另提供「恢复为 AI 选段」（先确认）。不得静默锁死或静默覆盖（KI-95）。

- **验收**：必留段进片率 **100%**；被勾选"必须记住的信息"覆盖率 **≥ 90%**；手动修改后改时长必弹询问，选「覆盖」后分镜表等于新选段结果

### FR-8 预览片（P0）

- 1080×1920 / 30fps，字幕压入，**只保留同期声，不加 BGM**
- 渲染时长 ≤ 3 分钟（3 分钟成片）
- 提供"未采用清单"：可用但没进片的片段 + 原因（时长/重复/未勾选必留），可试听、可一键加回（按时间插入分镜表，算一次手动修改）；界面在 ⑤ 看结果（GL-27）
- 预览片按当前分镜表生成，不产生版本号；分镜表改过后提示重新生成；生成过当前分镜表的预览片才能过闸门 B
- **验收**：预览与最终剪映工程内容一致（同一份 timeline 生成）；未采用清单里任一段点「加回」后出现在分镜表并在下一次预览片中出现

### FR-9 剪映工程导出（P0）

- 生成剪映草稿：视频轨 + 文本轨（字幕独立可编辑）
- 素材打包进草稿 `Resources/`，路径为安装后绝对路径
- 注册进剪映草稿库（先备份，失败回滚）
- 导出前跑静态校验，FAIL 不交付
- **验收**：macOS 剪映与 Windows 剪映打开并正确识别成功率 100%（两平台均已实测通过，见 §9）

### FR-10 版本与回退（P1）

- 每次导出生成新版本 `vN`，不覆盖（界面在 ⑥ 导出）
- 可对比两版：并排播放预览片 + 镜头差异（新增 / 删除 / 改字幕）（KI-94）
- 可回退：「回到这一版」把该版分镜表恢复为当前分镜表（先确认），不删除任何版本
- **验收**：同一项目连续生成 5 版，互不影响；旧版仍可打开

### FR-11 "不可用"标记（P1）

- 隐私/未授权片段在 ③ 看素材里标 ⊘（快捷键 X）后**永不进入候选**，也不进未采用清单（KI-93）
- 导出时自动排除；若已在手动分镜表里，标记后从分镜表移除并提示
- **验收**：标记后所有版本均不出现该片段

### FR-12 断点续做（P1）

- 分析中断/关闭应用后，重新打开从上次状态继续
- **验收**：强杀进程后重启，已完成阶段不重跑

### FR-13 诊断与日志（P1，已实现）

- 日志落 `~/Library/Logs/剪辑台/`（Win：`%LOCALAPPDATA%\剪辑台\logs`，随 Windows 安装包实现）
- 一键导出诊断包（含版本、阶段耗时 `work/timings.json`、错误栈、脱敏配置）
- **验收**：非技术用户可在 1 分钟内导出并发送

### FR-14 剪辑偏好（P1，已实现）

- 处理素材前可回答三问：更想保留信息还是情绪（`tone`）/ 片子给谁看（`audience`）/ 2–3 句指定原话（`must_lines`）
- 在新建项目时填写（可跳过），之后在「更多 → 项目设置」改；分析完成后改偏好，② 分析标「需要更新」
- 回答注入 b 路标注与内容摘要的提示词，并调整选段权重（信息优先 / 情绪优先）；指定原话整句匹配，找不到时给提示
- 存进 `project.json` 的 `calibration`（schema v2），随时可改、可重置；CLI `aicut.py calibrate`
- **验收**：改偏好后重新处理，标注提示词与选段权重随之变化；每句指定原话恰好多出 1 个强制镜头，匹配不到的给出提示

## 6. 数据模型

```
Project   { id, title, material, preset, platform, target_duration, created,
            schema_version, calibration{tone, audience, must_lines} }
Segment   { id, start, end, dur, category, level:废片|待定|可用, level_reason,
            summary, text, speaker, signals{energy, rate, overlap},
            visual{bright, motion, blur, flags},
            ocr, props（P2，见 FR-2）,
            must_keep: bool, usable: bool, used_in: [v1,v2] }
Category  { id, name, segments[], material_duration, usable_duration, budget }
Brief     一期不单独建模，由三处承载：
            calibration{tone, audience, must_lines}（FR-14，project.json）
            决策答案 → must_topics / exclude_topics / ending / focus / pacing
              （FR-6，work/brief_answers.json）
            target_duration / platform / preset（Project）
          one_message、structure：P2
Review    { analysis_confirmed, answers{question_id: option}, overrides[] }
Version   { name, timeline_path, preview_path, draft_name, created }
```

## 7. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 60 分钟素材：分析 ≤15 分钟；选段 ≤30 秒；渲染 3 分钟成片 ≤3 分钟 |
| 隐私 | 素材原片和画面帧不出本机。外发数据只有两类：16k 音轨 → 火山引擎 ASR；转写文本 → DeepSeek LLM。首次使用时告知用户这两条数据流（剪辑台首次打开弹出外发告知，CLI 在首次外发前要求 `aicut.py config consent`；未确认不外发）；日志与项目文件不得含 API Key |
| 平台 | macOS 13+，仅 Apple Silicon（不做 Intel / universal2）；Windows 10/11 x64 |
| 依赖 | 用户无需安装 Python/ffmpeg；交付形态见 §8 |
| 可靠性 | 任一阶段失败可重试且不产生半成品；草稿操作前必备份 |
| 成本 | 同一素材云端转写只计费一次（`work/transcript_raw.json` 已在且素材指纹未变即跳过）；输入未变时重跑处理沿用上次的标注与摘要，不重复调用 LLM；LLM 用量按项目累计记账（`work/llm_usage.json`，剪辑台项目信息行显示已用 tokens）。预算：每个项目默认 300 万 tokens，达到即停止调用模型并说明原因，可用环境变量 `AI_CUT_LLM_BUDGET_TOKENS` 调整（0 = 不限）；只统计 tokens，不折算金额（KI-32） |
| 断网与服务失败 | 只有转写与 AI 标注 / 摘要 / 提问需要联网；浏览、裁决、改分镜、预览、导出全部离线可用。云端失败时任务明确失败（中文原因 + 重试入口），不产生半成品、不静默降级：已提交的转写任务可续查（绑定音频指纹）；逐句标注失败时任务失败，已标注的句子先落盘，重试只补失败句；内容摘要与决策问题失败时退回兜底，并在界面标明是兜底结果；超出 LLM 预算同样明确失败。不做离线转写（PLAN §6） |
| 可维护性 | 预设、阈值、分类名外置为配置；核心流程有单测与校验器 |
| 可复现构建 | 依赖由 `uv.lock` 锁定；换机器 `uv sync` 即得一致环境；产物带校验和 |
| 许可合规 | 随包附第三方许可声明；ffmpeg 采用 LGPL 构建，不引入 GPL 组件（不含 libx264/libx265）；H.264 编码一律用 VideoToolbox（`h264_videotoolbox`） |
| 可用性 | 全流程中文文案；每个 AI 判断都可展开看依据 |

## 10. 成功指标（上线后 4 周）

样本默认：上线后 4 周内首批剪辑师交付的**全部**成片，且不少于 10 条（不足则顺延统计期）。记录汇总到 PROGRESS「上线后指标」表。

| 指标 | 目标 | 样本 | 测量方法 |
|---|---|---|---|
| 单条 3 分钟成片的人工时间 | ≤ 20 分钟（分配见 §3.3） | 全部成片，≥ 10 条 | 剪辑师用计时器记 S2–S4 的操作时间（不含等机器），每条一行 |
| 「重要内容是否丢失」满意度 | ≥ 80% | 全部成片，≥ 10 条 | 每条精剪完后问一题：没丢 / 丢了但不重要 / 丢了重要内容；满意 = 未选「丢了重要内容」；满意度 = 满意条数 ÷ 总条数 |
| 剪映工程打开成功率 | ≥ 95% | 全部导出（Mac、Windows 分别计） | 每次导出后记录「能打开并播放：是 / 否」；成功率 = 是 ÷ 总次数（放行检查样本须 100%，见 FR-9） |
| 平均返工轮次 | ≤ 1.5 | 全部项目 | 每个项目返工轮次 = `output/` 下版本数 − 1（每次出片生成一个 vN）；取平均 |
| 待定队列平均裁决时长 | ≤ 2 分钟 | 验收：PLAN §4 三条素材；上线后：全部项目 | 验收期人工计时；上线后用 `work/overrides.json` 中档位裁决的 `at` 时间戳，取同一次会话首条到末条的跨度作代理值 |
