## 0. 技术栈（已定）

完整清单见 **[TECH-STACK.md](TECH-STACK.md)**，关键约束三条：

- Python **3.11–3.12**，用 **uv** 隔离（`uv sync` 即得 3.12 环境，`uv.lock` 锁死 48 个包）；标准库 `http.server` + 原生 JS，不引框架；
- 媒体处理用 **ffmpeg 静态二进制**，剪映草稿用 **pyJianYingDraft**，桌面壳用 **pywebview**；
- 外部只依赖两个服务：**MediaKit（ASR，HTTPS 直连）+ DeepSeek API（LLM）**，Key 存 Keychain。

代码根目录：`/Users/developer/Documents/deepseek-harness/default-workspace`（已 `git init`，`projects/`、`dist/` 不入库）。

## 8. 完成定义（DoD）

每个里程碑（含上线里程碑 1–11）必须同时满足：

| 维度 | 门槛 | 怎么验 |
|---|---|---|
| 功能 | 对应 PRD 验收项逐条有记录（素材、数值、日期） | 记入 PROGRESS 对应行 |
| 回归测试 | 每个缺陷 / 新行为先写失败的回归测试，再改代码（TDD） | 提交里同时含测试 |
| 测试套件 | `uv run pytest` 全绿，用例数不减少 | 本地与提交前各跑一次 |
| 覆盖率 | ≥ 80%（KI-38 落地覆盖率门槛前，以用例数不减少为棘轮） | `uv run pytest --cov`（KI-38） |
| 代码审查 | 无 CRITICAL / HIGH 未决项 | `/ecc:code-review` 或 `/ecc:python-review` |
| 失败路径 | 失败有中文提示且不产生半成品（PRD §7 可靠性） | 对应回归测试 |
| 可用性 | 剪辑师不看文档完成该阶段操作 | 放行检查 / §4 验收 |
| 文档 | 登记册（GL / KI）状态填提交号；PRD / PLAN 口径冲突以 PRD 为准并同步 | `tests/test_docs_consistency.py` |
